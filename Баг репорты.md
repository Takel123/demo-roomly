## BUG-01: Форма позволяет забронировать переговорную на прошедшее время текущего дня

* **Приоритет:** High
* **Обоснование приоритета:**  Нарушается ключевое бизнес-требование — для текущего дня нельзя выбрать прошедшее время. Пользователь может забронировать переговорную на время, которое уже прошло.
* **Условия:** Chrome 157, Windows 11

**Шаги воспроизведения:**
1. Открыть страницу бронирования встреч `https://rcsi-science.github.io/demo-roomly/`.
2. В поле "Дата" указать сегодняшнюю дату.
3. В поле "Начало" указать время меньше текущего.
4. Заполнить остальные поля валидными данными
5. Нажать "Забронировать"

**Фактический результат:** 
Бронь успешно создана на прошедшее время текущего дня, сообщение об ошибке не отображается.

**Ожидаемый результат:** 
ошибка валидации о том, что для текущего дня нельзя выбрать прошедшее время, бронь не создаётся.

**Доказательства:**
* Скриншот: `attachments/bug1_error_2026-11-24_124601.png`
* Время на момент создания скриншота 12-46-01

## BUG-02: Не проверяется диапазон длительности встречи (30 мин - 4 часа)

* **Приоритет:** High
* **Обоснование приоритета:**  Нарушается ключевое бизнес-требование - длительность от 30 минут до 4 часов.
* **Условия:** Chrome 157, Windows 11

**Шаги воспроизведения (случай 1):**
1. Открыть страницу бронирования встреч `https://rcsi-science.github.io/demo-roomly/`.
2. В поле "Начало" указать время 10:00
3. В поле "Окончание" указать время 10:00 (длительность = 0)
4. Заполнить остальные поля валидными данными
5. Нажать "Забронировать"

**случай 2:**
Аналогично, но время окончания 10:15 (длительность = 15 мин)

**случай 3:**
Аналогично, но время окончания 15:00 (длительность = 5 часов)

**Фактический результат:** 
Бронь успешно создана во всех случаях

**Ожидаемый результат:** 
Ошибка: длительность должна быть от 30 минут до 4 часов

**Доказательства:**
* Скриншоты: `attachments/bug2_error.png`, `attachments/bug2_error2.png`, `attachments/bug2_error3.png`

## BUG-03: Форма позволяет забронировать переговорную с дробным количеством участников

* **Приоритет:** High
* **Обоснование приоритета:** Нарушается логика бизнес-требования к полю «Участники» (целое число от 1 до 20 и не больше вместимости комнаты) - количество людей не может быть дробным, система принимает некорректные данные.
* **Условия:** Chrome 157, Windows 11

**Шаги воспроизведения:**
1. Открыть страницу бронирования встреч `https://rcsi-science.github.io/demo-roomly/`.
2. В поле "Участники" ввести дробное число, например 2.5
3. Заполнить остальные поля валидными данными
4. Нажать "Забронировать"

**Фактический результат:** 
Бронь успешно создана с дробным значением в поле "Участники", сообщение об ошибке не отображается.

**Ожидаемый результат:** 
Отображается сообщение об ошибке валидации (либо ввод дробных символов блокируется полем), бронь не создаётся.

**Доказательства:**
* Скриншот: `attachments/bug3_error.png`

## BUG-04: Форма позволяет забронировать переговорную с некорректным форматом почты

* **Приоритет:** High
* **Обоснование приоритета:** Нарушается прямое требование к валидации (Электронная почта имеет корректный формат) - система принимает заведомо несуществующие адреса, из-за чего в реальном сценарии приглашение на встречу не будет доставлено.
* **Условия:** Chrome 157, Windows 11

**Шаги воспроизведения:**
1. Открыть страницу бронирования встреч `https://rcsi-science.github.io/demo-roomly/`.
2. В поле "Рабочая почта" ввести адрес в некорректном формате (Например, user@.domain.ru, user@domain.ru., user@domain..ru). Заполнить остальные поля валидными данными
3. Нажать "Забронировать"

**Фактический результат:** 
Бронь успешно создана с некорректным значением email, сообщение об ошибке не отображается.

**Ожидаемый результат:** 
Отображается сообщение об ошибке валидации формата электронной почты, бронь не создаётся.

**Доказательства:**
* Скриншот: `attachments/bug4_error.png`
